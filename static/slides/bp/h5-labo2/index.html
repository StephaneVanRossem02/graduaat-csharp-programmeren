Opwarmen

while of do while? 🤔

Welke loop past het best?

  1. Een menu tonen tot de gebruiker “stoppen” kiest → do while
  2. De getallen van 1 tot 10 tonen → while
  3. Een wachtwoord vragen tot het juist is → do while
  4. Woorden inlezen tot de gebruiker “stop” typt, ook als hij meteen “stop” typt → while

do while als het minstens één keer moet gebeuren, anders while.

do while is als een tweede kans bij een examen: eerst afleggen, dan pas beslissen of het opnieuw moet.

Complexe condities

Loops met ||

De voorwaarde van een loop is een booleaanse expressie, dus ook &&, || en ! mogen:

Console.WriteLine("Ben je ziek? (ja/nee)");
bool isSick = Console.ReadLine() == "ja";
Console.WriteLine("Ben je moe? (ja/nee)");
bool isTired = Console.ReadLine() == "ja";
while (isSick || isTired)
{
    Console.WriteLine("Blijf in bed!");
    Console.WriteLine("Ben je ziek? (ja/nee)");
    isSick = Console.ReadLine() == "ja";
    Console.WriteLine("Ben je moe? (ja/nee)");
    isTired = Console.ReadLine() == "ja";
}
Console.WriteLine("Opstaan!");

Blijf in bed zolang je ziek of moe bent. Voor sommige studenten een oneindige loop.

Twee redenen om te stoppen

Maximaal drie pogingen voor het juiste wachtwoord:

int attempts = 0;
string password = "";
while (password != "gEhEiM" && attempts < 3)
{
    Console.WriteLine("Wachtwoord?");
    password = Console.ReadLine();
    attempts++;
}

Met && gaat de loop door zolang alles klopt. Hij stopt zodra één van de voorwaarden false wordt: het wachtwoord is juist, of de pogingen zijn op.

Drie keer fout? Geblokkeerd. Net als je bankapp om drie uur ’s nachts.

Waarom stopte de loop?

Na de loop weet je niet waarom hij stopte. Controleer het met een if:

if (password == "gEhEiM")
{
    Console.WriteLine($"Welkom! Gelukt na {attempts} pogingen.");
}
else
{
    Console.WriteLine("Geblokkeerd.");
}
Wachtwoord?
fout
Wachtwoord?
gEhEiM
Welkom! Gelukt na 2 pogingen.

De loop zegt niet waarom hij stopte. Net als een collega die zonder uitleg naar huis vertrekt.

Hoe vaak? 🤔

int count = 0;
int total = 0;
while (count < 10 && total < 20)
{
    count++;
    total = total + count;
}
Console.WriteLine($"{count} {total}");
6 21

total wordt 1, 3, 6, 10, 15 en dan 21. Bij 21 is total < 20 false, dus de loop stopt, ook al is count nog maar 6.

21: het magische getal bij blackjack. Hier gewoon het einde van een loop.

Oneindige loops

Bewust oneindig

while (true)
{
    // code die nooit hoort te stoppen
}

Soms is dat gewenst: een game die steeds het scherm ververst, of een programma dat blijft wachten op invoer.

Tip

Een programma in de console stoppen? Ctrl + C, of in Visual Studio de rode stopknop (Shift + F5).

while (true): de loop die gelooft dat alles altijd waar is. Een optimist.

Per ongeluk oneindig

int counter = 0;
while (counter < 10)
{
    Console.WriteLine(counter);
}

counter blijft altijd 0. De voorwaarde wordt nooit false, dus de loop stopt nooit.

Oplossing: verander in de loop iets dat de voorwaarde beïnvloedt, hier counter++;.

Een loop zonder counter++ is als een hamster in een rad: veel beweging, geen vooruitgang.

De verraderlijke puntkomma

int count = 0;
while (count < 10);
{
    Console.WriteLine(count);
    count++;
}

De ; achter while (...) is een lege opdracht. Die wordt eindeloos herhaald, en het blok met accolades komt nooit aan de beurt.

Waarschuwing

Dit compileert gewoon! Visual Studio geeft enkel een waarschuwing: CS0642 “Possible mistaken empty statement”. Lees dus ook de groene kronkellijnen.

Eén puntkomma te veel, en je programma doet urenlang… niets. Heel efficiënt niets.

Checklist bij elke loop

  1. Heeft de voorwaarde een beginwaarde om mee te starten?
  2. Verandert er in de loop iets wat de voorwaarde beïnvloedt?
  3. Gaat die verandering in de goede richting, naar false toe?
  4. Staat er geen puntkomma achter while (...)?

Ctrl + C: de noodrem van de console. Geen boete voor misbruik.

Scope in loops

De som van 1 tot 10, fout

int counter = 1;
while (counter <= 10)
{
    int sum = 0;
    sum = sum + counter;
    counter++;
}
Console.WriteLine(sum);  // ❌ CS0103

Twee problemen:

  1. sum bestaat enkel binnen de accolades, dus na de loop niet meer.
  2. sum wordt in elke ronde opnieuw aangemaakt en op 0 gezet.

sum begint elke ronde opnieuw bij 0. Zoals je spaarrekening na de solden.

De som van 1 tot 10, juist

int counter = 1;
int sum = 0;
while (counter <= 10)
{
    sum = sum + counter;
    counter++;
}
Console.WriteLine(sum);  // 55

sum wordt één keer aangemaakt, vóór de loop. Elke ronde telt er iets bij, en na de loop kan je het resultaat tonen.

Gauss telde als kind 1 tot 100 op in zijn hoofd. Wij gebruiken een loop. En koffie.

Vuistregel

Wat? Waar declareren?
moet over de rondes heen bewaard blijven (teller, som, resultaat) vóór de loop
enkel nodig binnen één ronde (een tussenresultaat) mag in de loop
nodig in de voorwaarde van een do while vóór de loop

Wat je wil onthouden, hoort buiten de loop. Net als je sleutels: niet in de wasmachine.

Samengevat

Wat Onthoud
complexe conditie de voorwaarde zegt wanneer je doorgaat
na de loop controleer met een if waarom hij stopte
oneindige loop verander in de loop iets wat de voorwaarde beïnvloedt
puntkomma geen ; achter while (...), wel achter do { } while (...);
scope wat over rondes heen bewaard moet blijven: vóór de loop

Je weet nu hoe je een loop laat stoppen. Dat is meer dan de meeste vergaderingen.
